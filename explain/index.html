Claude Intelligence Wiring

A complete map of how the Claude Code AI assistant is configured in this repo — every hook, skill, subagent, context document, and database that shapes how Claude behaves when working on this project.

One-liner: The repo teaches Claude a structured workflow (discuss → safe-point → execute → verify → ship) enforced by hooks that fire automatically, with skills as named macro commands and a persistent knowledge database that survives session boundaries.

Big Picture

Everything lives under .claude/ (Claude Code config) and .ai/ (knowledge database). The diagram below shows how the pieces connect.

Hooks — Automatic Enforcement

Hooks are Python scripts wired to Claude Code lifecycle events in .claude/settings.json. They run automatically — Claude never has to remember to call them. All hooks fail open: any internal error exits with code 0 so a bug in a hook never locks you out.

Exit codes matter. Exit 0 = allow. Exit 2 = block the action and show the stderr message to Claude. Exit 1 = error (treated as allow, not a block).
EventMatcherScriptWhat it does
SessionStart — session_start.py Prints the last handoff block, active task, and pre-compact snapshot into Claude's context. Auto-rebuilds knowledge.db if any context/*.md file is newer than the DB.
PreToolUse Edit|Write safe_point_guard.py Reads context/revert-state.md — blocks the edit if no in-progress row exists for today's date. Forces Claude to run /safe-point before touching source code.
PostToolUse Edit|Write context_sync.py After every file edit: (1) if the file is under context/, runs .ai/sync_context.py to update SQLite; (2) runs ruff --fix if it's a .py file; (3) records current HEAD to .claude/.last_edit_hash.
PreCompact — precompact_snapshot.py Before the context window is summarised, writes a snapshot to context/session-snapshot.md and prepends a summary block to context/handoff.md. Then syncs SQLite. This is how state survives compaction.
Stop — check_handoff.py Before Claude stops: checks if source files changed this session but handoff.md was not updated. Also checks that /verifier was run since the last edit. Blocks if either condition fails.

SessionStart — session_start.py

Fires once when Claude Code opens a session. Injects recovery context so Claude doesn't start cold.

SessionStartsession_start.py

Reads: context/handoff.md (newest block, max 1500 chars), context/current-task.md (Active Task section), context/session-snapshot.md

Auto-rebuilds .ai/knowledge.db if any context/*.md is newer than the DB's mtime.

Prints a formatted summary into Claude's context window as the first thing it reads.

PreToolUse — safe_point_guard.py

The safety net. Prevents code edits without a recorded revert anchor for today.

PreToolUsesafe_point_guard.py

Exempt paths: context/, tasks/, .claude/ — only source code is guarded.

Check: reads context/revert-state.md, looks for a row with today's date and status in-progress.

If missing: exits 2 → Claude sees: "No safe-point recorded for today — run /safe-point first."

# revert-state.md row that satisfies the guard:
2026-09-24 | task: fix SMTP IPv4 | safe-point: abc123... | status: in-progress

PostToolUse — context_sync.py

Runs silently after every Edit or Write. Keeps SQLite in sync and code quality clean.

PostToolUsecontext_sync.py

1. If edited file is under context/ → runs .ai/sync_context.py (fast incremental SQLite sync)

2. If edited file is .py and ruff is available → runs ruff check --fix --quiet

3. Always → writes current git HEAD to .claude/.last_edit_hash

PreCompact — precompact_snapshot.py

Fires before Claude Code summarises the context window. Saves a full state snapshot so nothing is lost.

PreCompactprecompact_snapshot.py

Writes context/session-snapshot.md — current git HEAD, active task, files touched

Prepends a summary block to context/handoff.md

Syncs .ai/knowledge.db via sync_context.py

This is the key mechanism for surviving context compaction. When a new session starts after a compact, session_start.py reads the latest handoff block — which was written by this hook just before the compact.

Stop — check_handoff.py

Guards session exit. Ensures source changes are documented and verified before Claude stops.

Stopcheck_handoff.py

Checks: did any source file (not context/, tasks/, .claude/) change this session?

If yes: was context/handoff.md updated? Was /verifier run since the last edit?

If either fails: exits 2 → Claude is blocked from stopping until it runs /handoff or /verifier.

Skills — Named Macro Commands

Skills are Markdown files under .claude/skills/<name>/SKILL.md. When you type /skill-name, Claude Code loads that file as instructions and executes its steps. They're macros — a skill is just a structured prompt that tells Claude exactly what sequence of actions to take.

disable-model-invocation: true on some skills (execute, discuss, ship-main) means Claude reads and follows the skill inline rather than spinning up a separate model call.

/discuss

/discuss

Purpose: Alignment before coding. Forces a plan/trade-off conversation before any file is touched.

Steps: state goal → propose approach → surface trade-offs → enter plan mode → iterate → on approval: exit plan mode and execute.

Use when: "discuss X", "plan X", or you hit a decision point.

/execute

/execute

Purpose: Full auto-permissions for an agreed plan. Proceeds through edits, shell commands, and context updates without stopping.

Auto-approves: file edits, writes, read-only shell, git add, commits.

Still requires confirmation: git push, DB drops, deleting files not created this session.

On completion: runs /task-done + /verifier if source changed + prints impact stats.

Use when: "execute", "go", "do it".

/safe-point

/safe-point

Purpose: Record a revert anchor before touching source code. Required by the safe_point_guard hook.

Steps: git rev-parse HEAD → append row to context/revert-state.md → python .ai/sync_context.py

Row format: YYYY-MM-DD | task: <desc> | <hash> | in-progress

/task-done

/task-done

Purpose: Mini-handoff after every discrete subtask. Keeps context docs and DB in sync without pushing.

Steps (in order, no skipping):

1. Append complete row to revert-state.md

2. Update context/current-task.md (move item to Completed)

3. Update context/backlog.md (check off, log row)

4. Update architecture/decisions/constraints docs if changed

5. Run python .ai/sync_context.py

6. Append line to context/savings-log.md

7. Run python .claude/hooks/task_complete_stats.py and print output

/ship-main

/ship-main

Purpose: Manual-only skill. Runs /task-done then commits and pushes to main.

Only triggers when: user explicitly says "ship" or "ship to main". Never called automatically.

Steps: /task-done → git status → git add specific files → commit with attribution → git pull --rebase → git push origin main

Never force-push. Never skip rebase. Commit attribution: Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>

Subagents — Specialised Read-Only Workers

Subagents are defined in .claude/agents/*.md. They're spun up by the main Claude session when a task benefits from isolation or parallelism. All four agents in this repo are read-only — they query and report, never edit.

librarian

Answers "where is X in the codebase?" — queries SQLite first, then reads files to verify exact line numbers. Returns file paths with line references.

verifier

Runs the verification procedures from context/verification.md — build checks, lint, import checks. Reports pass/fail with exact output. Never edits source.

explorer

Surveys a major area of the codebase and returns a draft of the relevant context/*.md content. Used by /build-intelligence to populate knowledge from scratch.

context-auditor

Compares claims in context/*.md against source code and git log since each doc's staleness marker. Reports outdated, missing, or wrong statements with evidence.

SQLite Knowledge Database — .ai/knowledge.db

The database is a queryable index over all context docs and the codebase structure. It lets Claude find things with a SQL query instead of scanning files.

Tables

realignment — single-row recovery pointer (what to load first)

context_documents — name, path, description, tags for each context/*.md

files — key source files with path, description, tags

dependencies — source → target relationships between files

constraints — hard constraints with severity (hard/soft)

failed_solutions — past failures by area, title, lesson

Sync scripts

.ai/sync_context.py — fast incremental sync, re-indexes only changed context/*.md files. Called automatically by context_sync.py hook after every context doc edit.

.ai/rebuild_db.py — full rebuild including file index and dependency graph. Called by session_start.py when DB is stale. Run manually when file structure changes.

How to query it

-- Find context docs by topic
SELECT name, path, description FROM context_documents WHERE tags LIKE '%auth%';

-- Find key files by area
SELECT path, description FROM files WHERE tags LIKE '%categorization%';

-- Check hard constraints before modifying anything
SELECT title, description FROM constraints WHERE severity = 'hard';

-- Check if an approach has been tried and failed
SELECT title, lesson FROM failed_solutions WHERE area = 'web';

Typical Session Flow

Here's what happens from the moment you open Claude Code to when you ship a change.

1 — Session Opens (automatic)
session_start.py fires. Prints last handoff, active task, and snapshot into context. Rebuilds knowledge.db if stale. Claude starts with full context, no cold-start scanning.
2 — Plan the change (/discuss)
User types /discuss fix the email bug. Claude proposes approach, surfaces trade-offs, enters plan mode. No code written yet. User says "go" to approve.
3 — Record anchor (/safe-point)
Before touching any source file, Claude runs /safe-point. Appends today's date + HEAD hash + in-progress to revert-state.md. This satisfies the safe_point_guard hook. If skipped, the hook blocks the first Edit call.
4 — Execute (/execute)
Claude edits files, runs commands, commits — all with auto-approval. After each file edit, context_sync.py fires: syncs SQLite if a context doc changed, runs ruff on Python files, records HEAD hash. Claude gives rolling status updates.
5 — Wrap up (/task-done)
Claude runs /task-done: marks safe-point complete, updates current-task.md and backlog.md, updates architecture/constraint docs if needed, syncs SQLite, appends to savings log, prints impact stats.
6 — Ship (/ship-main)
User says "ship". Claude: stages only relevant files (reviews diff for secrets), commits with attribution, git pull --rebase, git push origin main. Never auto-triggered — user must say the word.
7 — Session ends (automatic)
check_handoff.py fires. If source files changed: checks handoff updated + verifier run. Blocks exit if either missing. On the next session, the PreCompact snapshot (if one was written) is injected as the first thing Claude reads.

Permissions — .claude/settings.json

The permissions block controls what Claude Code can do without asking. Currently configured to allow free writes to internal project folders and deny reading the client-facing HTML report.

{
  "permissions": {
    "allow": [
      "Edit(context/**)",    // context docs — auto-approved
      "Edit(tasks/**)",      // task tracking — auto-approved
      "Edit(.claude/**)",    // skills/hooks/settings — auto-approved
      "Write(context/**)",
      "Write(tasks/**)",
      "Write(.claude/**)"
    ],
    "deny": [
      "Read(context/overview.html)"  // client-facing report — never read by Claude
    ]
  }
}
Source code edits (anything not in context/, tasks/, .claude/) are NOT in the allow list — they go through the normal permission prompt + the safe_point_guard hook.
